GPIO Pins & Why Headers Are Not Pre-Soldered

GPIO Pins & Labels

Pins are labeled on the underside. GPIO pins are named GP0–GP28. Important power & control pins include: 3V3, VBUS, VSYS, GND, and RUN. Note: numbering starts at 0.

Why Headers Aren't Pre-Soldered

Pico boards ship flat so they can be soldered directly onto other PCBs (lower profile for embedded systems). For prototyping with breadboards, solder 2.54 mm male pin headers.

Core Concepts: What is Raspberry Pi Pico?

Raspberry Pi Pico is a microcontroller development board designed for physical computing and embedded control tasks. It runs bare-metal firmware (no operating system) and boots extremely quickly with low power consumption.

info Key Distinctions

Unlike a Raspberry Pi computer (which runs Linux and supports desktop peripherals), the Pico runs a single program and is optimized for sensors, LEDs, motors, and other embedded tasks.

Powered by

  • RP2040 — Pico / Pico W
  • RP2350 — Pico 2 / Pico 2 W

Use Cases

  • Controlling LEDs, buttons, sensors, motors, displays
  • Low-power embedded control and rapid prototyping

Hardware Tour

  • Micro USB: Power and UF2 file transfer
  • BOOTSEL button: Hold while plugging in to enter UF2 flashing mode
  • RP2040 / RP2350: The main processor
  • GPIO: GP0–GP28 for digital I/O
  • Power pins: 3V3, VBUS, VSYS and GND
  • Castellated edges & debug pads: For embedded mounting and professional debugging
  • Wireless modules: Pico W / Pico 2 W add Wi‑Fi/Bluetooth

Practical Procedure: Installing MicroPython

Enter BOOTSEL Mode

  1. Hold down BOOTSEL while plugging the Pico into your computer via USB. Release after 2–3 seconds. The Pico appears as a USB mass storage device.
  2. Open the Pico drive and follow the INDEX.HTM link to Raspberry Pi documentation if unsure which UF2 to use.
  3. Download the correct .uf2 for your board (Pico, Pico W, Pico 2, Pico 2 W) and drag it onto the Pico drive.
  4. Flash: Pico will automatically reboot and the drive will disappear once flashing completes.
warning Note: MicroPython will remain installed until a different firmware replaces it.

What is MicroPython?

MicroPython is a lightweight, Python-compatible language designed to run directly on the RP2040/RP2350 microcontroller with hardware-specific libraries and reduced memory footprint.

Core Concepts

Physical computing uses code to sense and control the real world via hardware. The Pico bridges software logic (MicroPython) and devices like LEDs, buttons, sensors, displays and motors.

Estimated Time

~20–40 minutes (mostly conceptual; prepares for hands-on wiring in later chapters)

Raspberry Pi Pico: Pins Overview

The Pico exposes pins grouped by function rather than sequential physical numbers. Key categories and purposes:

Pin TypePurpose
3V3 (OUT)Regulated 3.3V output
VBUS5V from USB
VSYSMain system power input (2–5V)
GNDGround (0V reference)
GP0–GP28GPIO (digital input/output)
GPxx_ADCxGPIO with analogue input (ADC)
ADC_VREFAnalogue reference voltage
AGNDAnalogue ground
RUNEnable / disable Pico (reset control)

Key ideas: GPIO numbering starts at GP0, GPIO numbers are not the same as physical pin numbers, some GPIOs support analogue input, and never exceed 3.3V on GPIO inputs.

GPIO Pins (Digital I/O)

GPIO pins can be programmed as outputs (e.g., LEDs, buzzers) or inputs (e.g., buttons, sensors). They have no fixed role until defined in MicroPython. Important: Pico GPIOs are 3.3V logic only.

Electronic Components Introduced

ComponentRoleInput / Output
ResistorLimits currentPassive
Jumper wiresElectrical connectionsPassive
LEDLight indicatorOutput
PIR sensorMotion detectionInput
BreadboardPrototypingPassive

Key Component Concepts

  • Resistors: measured in ohms (Ω); protect LEDs and GPIO pins. Common values: 330Ω for LED protection; 8.2kΩ–20kΩ for sensors and pull-ups.
  • LEDs: polarity matters (long leg = +); always use a resistor; use LEDs rated for 3.3V.
  • Buzzers: active buzzers are simpler and can be driven directly by GPIO.
  • Potentiometers: variable resistor (2 pins) or voltage divider (3 pins); use with ADC pins.

Resistor Colour Code System

Read bands left → right. First two bands = digits, next = multiplier, final = tolerance.

Example: Orange – Orange – Brown – Gold → 33 × 10¹ = 330Ω

Common units: 1,000Ω = 1kΩ, 1,000,000Ω = 1MΩ.

The machine Library

MicroPython's machine library provides hardware access (Pin class) required to control GPIO pins.

GPIO as Outputs

Use machine.Pin to configure outputs. Example for the on-board LED:

import machine

led_onboard = machine.Pin("LED", machine.Pin.OUT)
led_onboard.value(1)  # turn on
led_onboard.value(0)  # turn off

Timing & Loops

Use time.sleep() and loops to make visible LED behavior.

Using a Breadboard (Safety)

Breadboards connect rows and have a center gap; Pico should straddle the gap. Use power rails for VCC/GND. Warnings: never short pins, never force bent pins, disconnect USB power when wiring.

Project 1 — Hello, LED! (On-board LED)

Turn the Pico's built-in LED on and off.

import machine

led_onboard = machine.Pin("LED", machine.Pin.OUT)
led_onboard.value(1)  # on
# to turn off
led_onboard.value(0)

Project 2 — External LED (GP15)

Use a 330Ω resistor to protect the LED.

import machine

led_external = machine.Pin(15, machine.Pin.OUT)
led_external.value(1)  # turn external LED on

Project 3 — Reading a Push-Button (GP14)

Configure input with a pull-up resistor; button press pulls input LOW (0).

import machine

button = machine.Pin(14, machine.Pin.IN, machine.Pin.PULL_UP)
print(button.value())

Continuous reading example:

import machine
import time

button = machine.Pin(14, machine.Pin.IN, machine.Pin.PULL_UP)

while True:
    if button.value() == 0:
        print("You pressed the button!")
        time.sleep(2)

Project 4 — Input + Output Together

Use a button to control an LED (LED on GP15, Button on GP14).

import machine
import time

led_external = machine.Pin(15, machine.Pin.OUT)
button = machine.Pin(14, machine.Pin.IN, machine.Pin.PULL_UP)

while True:
    if button.value() == 0:
        led_external.value(1)
        time.sleep(2)
    led_external.value(0)

Chapter 5 — Traffic Light Controller

Learning Points

  • Control multiple output devices (LEDs, buzzer) with MicroPython
  • Implement timed state machines using time.sleep()
  • Use push-button input with internal pull-up resistors
  • Understand and apply hardware interrupts (IRQs)
  • Safely manage shared state between interrupt handlers and main loops
  • Simulate a real-world embedded system (pedestrian traffic lights)

Key Concepts

Traffic light controllers are finite state machines. The pedestrian crossing introduces an event-driven override triggered by a button press; interrupts provide an immediate, non-blocking way to handle that event.

Hardware Required

  • Raspberry Pi Pico
  • Breadboard
  • Red, Amber, Green LEDs
  • 3 × 330 Ω resistors
  • Push-button switch
  • Active piezo buzzer
  • Jumper wires, Micro USB cable

Traffic Light Logic (State-Based Systems)

A traffic light controller cycles through: Red → Red + Amber → Green → Amber → Repeat. A pedestrian button press requests a crossing and triggers an interrupt-driven response.

GPIO Outputs — LEDs

  • Red LED — GP15
  • Amber LED — GP14
  • Green LED — GP13
  • Use 330 Ω current-limiting resistors

Button & Buzzer

  • Push button to GND on GP16; configure as Pin.IN, Pin.PULL_UP
  • Active buzzer on GP12

Wiring Summary

ComponentGPIO Pin
Red LEDGP15
Amber LEDGP14
Green LEDGP13
Push ButtonGP16
BuzzerGP12
GroundGND

Core MicroPython Code (Pedestrian Crossing)

import machine
import time

# LEDs
led_red = machine.Pin(15, machine.Pin.OUT)
led_amber = machine.Pin(14, machine.Pin.OUT)
led_green = machine.Pin(13, machine.Pin.OUT)

# Button and buzzer
button = machine.Pin(16, machine.Pin.IN, machine.Pin.PULL_UP)
buzzer = machine.Pin(12, machine.Pin.OUT)

button_pressed = False

# Interrupt handler
def btn_handler(pin):
    global button_pressed
    if not button_pressed:
        button_pressed = True

# Enable interrupt
button.irq(trigger=machine.Pin.IRQ_FALLING, handler=btn_handler)

while True:
    # Pedestrian crossing
    if button_pressed:
        led_red.value(1)
        for i in range(20):
            buzzer.value(1)
            time.sleep(0.05)
            buzzer.value(0)
            time.sleep(0.2)
        button_pressed = False

    # Traffic light cycle
    led_red.value(1)
    time.sleep(5)

    led_amber.value(1)
    time.sleep(2)

    led_red.value(0)
    led_amber.value(0)
    led_green.value(1)
    time.sleep(5)

    led_green.value(0)
    led_amber.value(1)
    time.sleep(5)

    led_amber.value(0)

This mimics a UK-style puffin crossing where the red light stays on after the buzzer stops to allow pedestrians time to finish crossing.

What This Program Demonstrates

  • Concurrent behavior using interrupts
  • Non-blocking input handling
  • Time-based sequencing
  • Safe shared-variable design
  • Real-world embedded modeling

In-Chapter Challenges (Exercises)

  • Basic: Increase pedestrian crossing time; change LED timing values
  • Intermediate: Add a second pedestrian button; modify sequence to match another country's traffic system
  • Advanced: Replace delays with a full state machine; add night mode or flashing amber mode; display countdown on an OLED

Chapter 6 — Reaction Game

Learning Objectives

  • Understand reaction time and mental chronometry
  • Build a single-player and two-player reaction game
  • Use GPIO input and output together
  • Apply interrupts for instant response
  • Implement random delays for unpredictable behavior
  • Design an interactive game using MicroPython

Core Concepts

  • Reaction Time: 200–250 ms average for humans
  • Randomness: Prevents prediction; ensures fairness
  • Pull-Up Resistors: Prevent floating inputs
  • Interrupts: Real-time button detection
  • Game Logic: Input, output, state management

Hardware Required

  • Raspberry Pi Pico
  • Breadboard
  • 1–2 × Push-buttons
  • 1 × LED (any color)
  • 1 × 330 Ω resistor
  • Jumper wires
  • Micro USB cable

Reaction Time (Mental Chronometry)

Reaction time is the delay between a stimulus and a response.

  • Average human: 200–250 ms
  • LED turning OFF = signal to press button
  • Randomness prevents players from counting seconds

Game Components & Roles

ComponentRole
LEDVisual signal (start/stop cue)
Push-button(s)Player input
PicoGame controller

Single-Player Circuit Overview

  • LED → GP15 (with 330 Ω resistor)
  • Button → GP14 (with internal pull-up, wired to GND)

Single-Player Reaction Game Code

import machine
import time
import random

button_pressed = False

led = machine.Pin(15, machine.Pin.OUT)
button = machine.Pin(14, machine.Pin.IN, machine.Pin.PULL_UP)

def btn_handler(pin):
    global button_pressed
    if not button_pressed:
        button_pressed = True
        print(pin)

led.value(1)
time.sleep(random.uniform(5, 10))
led.value(0)

button.irq(trigger=machine.Pin.IRQ_FALLING, handler=btn_handler)

How it works: LED turns ON → Pico waits 5–10 seconds (randomized) → LED turns OFF → player must press button as quickly as possible.

Two-Player Game (Expansion)

  • Left button: GP14 (with pull-up)
  • Right button: GP16 (with pull-up)
  • First button pressed wins
  • Pico prints winner to the Shell
  • Game resets on re-run

Key Skills & Concepts Reinforced

  • Event-driven programming using interrupts
  • GPIO input and output combined in one project
  • Game-state control using flags
  • Combining randomness with hardware inputs
  • Real-time response to physical events

Challenges & Extensions

  • Built-in: Change victory messages; add a third player; measure reaction time
  • Suggested: Add an OLED screen for reaction time display; store best time in memory; use a buzzer for signals; turn into a classroom competition

Chapter 7: Burglar Alarm

school Key Concepts

settings Key Components Used

  • Raspberry Pi Pico / Pico W

3.1 Passive Infrared (PIR) Sensor

  • Detects heat movement from people or animals
  • Uses a Fresnel lens to widen its field of view
  • Outputs a digital HIGH signal when motion is detected
  • Includes adjustable delay potentiometers
⚠️ Warning: HC-SR501 requires 5V power, not 3.3V. Use VBUS (Pin 40) on the Pico

3.2 Interrupts (IRQs)

Interrupts allow the Pico to react immediately. PIR sensor triggers on rising edge. No infinite loop required to keep checking the sensor.

snsr_pir.irq(
    trigger=machine.Pin.IRQ_RISING,
    handler=pir_handler
)

3.3 Debouncing

PIR sensors can produce noisy signals. Debouncing confirms the signal is stable before acting.

time.sleep_ms(100)  # Wait 100 ms
if pin.value():      # Confirm signal is still HIGH
    # Prevents false alarms

Step 1: Read PIR Sensor and Print Alert

import machine
import time

snsr_pir = machine.Pin(28, machine.Pin.IN)

def pir_handler(pin):

8. Final Complete Program

import machine
import time

snsr_pir  = machine.Pin(28, machine.Pin.IN)
snsr_pir2 = machine.Pin(18, machine.Pin.IN)

led    = machine.Pin(15, machine.Pin.OUT)
buzzer = machine.Pin(14, machine.Pin.OUT)

def pir_handler(pin):
    time.sleep_ms(100)
    if pin.value():
        if pin is snsr_pir:
            print("ALARM! Motion detected in bedroom!")
        elif pin is snsr_pir2:
            print("ALARM! Motion detected in living room!")

        for i in range(50):
            led.toggle()
            buzzer.toggle()
            time.sleep_ms(100)

snsr_pir.irq(trigger=machine.Pin.IRQ_RISING, handler=pir_handler)
snsr_pir2.irq(trigger=machine.Pin.IRQ_RISING, handler=pir_handler)

while True:
    led.toggle()
    time.sleep(5)

school Core Concepts

  • ADC: Converts analogue signals to digital
  • Resolution: 12-bit hardware, 16-bit in MicroPython

  • PWM: Simulates analogue output digitally
  • Duty Cycle: Controls brightness and output

settings Key Components

  • Raspberry Pi Pico / Pico W
  • Potentiometer (10kΩ recommended)
  • LED + 330 Ω resistor
  • Breadboard + jumper wires
  • 3.3V and GND rails

2.1 Analogue vs Digital Signals

  • Digital: ON or OFF (0 or 1)
  • Analogue: Continuous range of values (e.g., 0–3.3V)
  • Microcontrollers are digital, so they require an ADC to interpret analogue signals

2.2 Analogue-to-Digital Converter (ADC)

Pico ADC Resolution:

  • Hardware: 12-bit
  • MicroPython output: 16-bit (0–65,535)

ADC Channels:

  • GP26 → ADC0
  • GP27 → ADC1
  • GP28 → ADC2
  • Internal temp → ADC4

Why 65,535? 16-bit binary maximum = 1111111111111111 → 65,535 decimal.

2.3 Conversion Factor

To convert ADC readings into voltage:

conversion_factor = 3.3 / 65535

This maps ADC values to real-world voltage (0–3.3V).

2.4 Potentiometer as a Voltage Divider

  • Acts as: Variable resistor
  • Voltage divider when connected to 3.3V and GND
  • Output voltage changes smoothly as knob turns
⚠️ Note: Real components never reach perfect 0 or 3.3V due to tolerance.

2.5 Internal Temperature Sensor

  • Located inside the RP2040 / RP2350 chip
  • Reports voltage proportional to temperature
  • Requires a datasheet-derived formula:
temperature = 27 - (reading - 0.706) / 0.001721
⚠️ Note: Sensor measures chip temperature, not ambient air temperature.

2.6 Pulse-Width Modulation (PWM)

  • Used to simulate analogue output using digital pins
  • Works by changing the duty cycle
  • All GPIO pins support PWM
  • PWM is divided into slices (two pins per slice)
⚠️ Warning: Using both outputs of the same PWM slice causes conflicts.

Practice 1: Reading a Potentiometer (Raw ADC)

Goal: Observe raw ADC values

import machine
import time

pot = machine.ADC(26)

while True:
    print(pot.read_u16())
    time.sleep(0.5)

Practice 2: Convert ADC Reading to Voltage

import machine
import time

pot = machine.ADC(26)
conversion_factor = 3.3 / 65535

while True:
    voltage = pot.read_u16() * conversion_factor
    print(voltage)
    time.sleep(0.5)

Practice 3: Reading Internal Temperature Sensor

import machine
import time

sensor_temp = machine.ADC(machine.ADC.CORE_TEMP)
conversion_factor = 3.3 / 65535

while True:
    reading = sensor_temp.read_u16() * conversion_factor
    temperature = 27 - (reading - 0.706) / 0.001721
    print(temperature)
    time.sleep(2)

Experiment: Touch the Pico chip with your finger and observe temperature changes.

Practice 4: Fading an LED with PWM

import machine
import time

led = machine.PWM(machine.Pin(15))
led.freq(1000)

while True:
    for duty in range(0, 65535, 500):
        led.duty_u16(duty)
        time.sleep(0.01)
    for duty in range(65535, 0, -500):
        led.duty_u16(duty)
        time.sleep(0.01)

school I2C Protocol

2.1 Why Use Digital Protocols?

As projects grow, GPIO pins alone aren't enough. Sensors, displays, and modules often use standardized digital protocols to exchange data efficiently.

MicroPython supports:

  • I2C (Inter-Integrated Circuit)
  • SPI (Serial Peripheral Interface)

2.2 Voltage Levels

⚠️ Warning:

  • Raspberry Pi Pico GPIO operates at 3.3V
  • Many I2C/SPI devices also support 5V → this can damage the Pico
  • Always verify device voltage compatibility before wiring

3. I2C Protocol

3.1 I2C Basics

2 wires only:

  • SDA – Data
  • SCL – Clock
  • Supports multiple devices on the same bus
  • Devices are identified by a unique address (e.g., 0x3C)

Advantages:

  • Fewer wires
  • Great for many low-speed peripherals

Limitations:

  • Address conflicts possible
  • Slightly slower than SPI

3.2 I2C Pins on Pico

Two buses: I2C0 and I2C1

Example used in the book:

  • SDA → GP0
  • SCL → GP1

3.3 I2C OLED (SSD1306) Wiring

OLED Pin Pico Pin
VCC 3.3V
GND GND
SDA GP0
SCL GP1

Note: Pull-up resistors usually included on the module

Helps identify connected devices and their addresses:

import machine

sda = machine.Pin(0)
scl = machine.Pin(1)

i2c = machine.I2C(0, sda=sda, scl=scl, freq=400000)

4. SPI Protocol

4.1 SPI Basics

4 wires:

  • SCK – Clock
  • MOSI – Data to device
  • MISO – Data from device
  • CS – Chip Select

No addressing → devices selected using CS pins

Advantages:

  • Faster
  • No address conflicts

Limitations:

  • More wiring
  • One CS pin per device

4.2 SPI OLED Wiring (SSD1306 SPI)

Key Concepts Explained

1. Bluetooth Low Energy (BLE)
  • Designed for short-range, low-power communication
  • Ideal for IoT sensors
  • Uses advertising beacons instead of persistent connections
  • Supported natively by Pico W and Pico 2 W radios
2. BLE Advertising
  • Devices broadcast what services they offer
  • Other devices can scan and connect if interested
  • No constant connection required → low power
  • BLE devices advertise, they don’t “push data” like Wi-Fi
3. UUIDs (Universally Unique Identifiers)

Services and characteristics are identified using UUIDs:

  • Service UUID: What the device does (e.g., 0x181A)
  • Characteristic UUID: What data it provides (e.g., 0x2A6E)
4. aioble Library

Wraps MicroPython’s bluetooth module and removes boilerplate code. Supports:

  • Advertising
  • Services & characteristics
  • Notifications & Async operations
5. Asynchronous Programming (asyncio)

Used to run tasks concurrently without blocking, like reading a sensor while transmitting BLE data.

BLE broadcasting continues while sensor readings update.

Hands-On Project: BLE Temperature Sensor

Project 1 – BLE Temperature Beacon (Transmitter)

This project reads the Pico's internal temperature sensor, encodes the temperature into a BLE payload, and advertises it every 2 seconds.


import struct
import asyncio
import aioble
import bluetooth
import machine

# Temperature Setup
sensor_temp = machine.ADC(machine.ADC.CORE_TEMP)
conversion_factor = 3.3 / 65535

# BLE Configuration
ble_name = "picow_ble"
ble_svc_uuid = bluetooth.UUID(0x181A)
ble_characteristic_uuid = bluetooth.UUID(0x2A6E)
ble_appearance = 0x0300
ble_advertising_interval = 2000

# BLE Service & Characteristic
ble_service = aioble.Service(ble_svc_uuid)
ble_characteristic = aioble.Characteristic(
    ble_service,
    ble_characteristic_uuid,
    read=True,
    notify=True
)
aioble.register_services(ble_service)

# Temperature Encoding Helper
def encode_temp(temp):
    return struct.pack("<h", int(temp * 100))

# Sensor Task (Async)
async def sensor_task():
    while True:
        reading = sensor_temp.read_u16() * conversion_factor
        temperature = 27 - (reading - 0.706) / 0.001721
        ble_characteristic.write(encode_temp(temperature))
        print("Temperature:", temperature)
        await asyncio.sleep_ms(2000)

# BLE Advertising Task
async def ble_task():
    while True:
        await aioble.advertise(
            ble_advertising_interval,
            name=ble_name,
            services=[ble_svc_uuid],
            appearance=ble_appearance
        )

# Main Event Loop
async def main():
    task1 = asyncio.create_task(ble_task())
    task2 = asyncio.create_task(sensor_task())
    await asyncio.gather(task1, task2)

print("Launching Raspberry Pi Pico W BLE temperature sensor...")
asyncio.run(main())
